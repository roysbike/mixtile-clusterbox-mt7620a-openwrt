# ClusterBox BMC firmware v0.2.0-rc.1

**In one sentence:** the gateway from the LAN and internet to the
blades gets ~1.5x faster: blades with the v0.4 driver fetch their
frames from BMC memory with their own DMA.

This is the BMC part of **OpenMIOP Stack v0.4.0-rc.1**, with
[pcie-ep-net v0.4.0-rc.1](https://github.com/roysbike/pcie-ep-net/releases/tag/v0.4.0-rc.1)
and [mixtile-talos v0.4.0-rc.1](https://github.com/roysbike/mixtile-talos/releases/tag/v0.4.0-rc.1).
Either side can be updated first; blades on mixtile-talos v0.3.0 keep
working with this firmware (old path, same speed as before).

> [!WARNING]
> Updating reboots the BMC, and the BMC is the PCIe root complex: every
> blade link resets. Blades on mixtile-talos v0.3.0 or later reconnect to
> each other in ~12 s by themselves and keep their NVMe. Check
> `nodectl status --all`, etcd and DRBD after.

## What's new since v0.1.1

- **Gateway pull** (`omi-rc` from pcie-ep-net v0.4.0-rc.1). Until now the
  BMC wrote every frame for a blade into the blade's PCIe BAR with its
  CPU, one 32-bit write per word: ~90 Mbit/s from the LAN to a blade
  with the BMC CPU at 99 %. Now the BMC copies the frame into its own RAM
  and the blade reads it with an eDMA read channel.
- **Firewall flow offloading on by default.** The BMC routes and NATs
  all blade traffic; offloading takes ~10 points of CPU off that. Set
  only if `firewall.@defaults[0].flow_offloading` is not set yet.

Full list: [CHANGELOG.md](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/blob/v0.2.0-rc.1/CHANGELOG.md).

## Download

| You want to | File |
| --- | --- |
| Update from v0.1.0-rc.4 or later | LuCI *System → Firmware Update* (`rc` channel), or see *Update* |
| Install on other ClusterBox firmware | `openmiop-0.2.0-rc.1-clusterbox-bmc-openwrt-23.05-mipsel-sysupgrade.bin` + `clusterbox-firmware.json` + `mixtile-update` |
| Check what you downloaded | `SHA256SUMS`, `BUILD-INFO.txt` |

## Update

```sh
uci set mixtile-update.main.channel=rc; uci commit mixtile-update   # release candidates
mixtile-update check && mixtile-update download && mixtile-update verify && mixtile-update install --yes
```

After the reboot:

```sh
cat /etc/mixtile-release                      # FIRMWARE_VERSION="v0.2.0-rc.1"
dmesg | grep omi0                             # "node N active: ..., gateway pull" for v0.4 blades
uci get firewall.@defaults[0].flow_offloading # 1
nodectl status --all                          # every blade powered, LINK Gen3 x2
```

## Tested

On the lab Cluster Box, with the `omi-rc` of this release (same code,
built by CI) loaded by hand on firmware v0.1.1 and flow offloading
switched on by hand; .108 on a mixtile-talos test image with the v0.4
driver, .133 on v0.3.0, measured at the same time:

| | blade with gateway pull | v0.3.0 blade |
| --- | --- | --- |
| LAN -> blade through the BMC | 141-145 Mbit/s | 92-95 Mbit/s |
| Internet -> blade | 152-155 Mbit/s | 97-106 Mbit/s |
| BMC -> blade, no NAT | 204 Mbit/s | 130 Mbit/s |
| Blade -> LAN | 264-272 Mbit/s | 267-276 Mbit/s |

444 158 frames pulled, 0 errors. Flow offloading alone: blade -> LAN
207-210 -> 247-251 Mbit/s, BMC CPU 95 -> 85 %.

The full v0.2.0-rc.1 image was not flashed before the release; its
contents are verified in CI (`scripts/clusterbox/verify-firmware.sh`).

## Known issues

- The BMC CPU (one MIPS core) is the gateway limit now: ~140-150 Mbit/s
  to a blade, ~270 Mbit/s from a blade.
- Otherwise as in [v0.1.1](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/releases/tag/v0.1.1).
