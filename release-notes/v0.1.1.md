# ClusterBox BMC firmware v0.1.1

**In one sentence:** a patch release whose `omi-rc` no longer keeps
the BMC load average at 1.00 on an idle Cluster Box.

This is the BMC part of **OpenMIOP Stack v0.3.1**, with
[pcie-ep-net v0.3.1](https://github.com/roysbike/pcie-ep-net/releases/tag/v0.3.1).
The blades stay on
[mixtile-talos v0.3.0](https://github.com/roysbike/mixtile-talos/releases/tag/v0.3.0):
the blade driver did not change.

> [!WARNING]
> Updating reboots the BMC, and the BMC is the PCIe root complex: every
> blade link resets. Blades on mixtile-talos v0.3.0 reconnect to each
> other in ~12 s by themselves and keep their NVMe. Check
> `nodectl status --all`, etcd and DRBD after.

## What's new since v0.1.0

- **`omi-rc`: idle sleep.** The module's control thread paused 1-2 ms
  between passes with an uninterruptible sleep and so sat in D state;
  Linux counts that in the load average, which stayed at 1.00 on an
  idle BMC. The thread now sleeps the same time in `TASK_IDLE`.
  Behaviour and timing are unchanged.
- `openmiop` and `kmod-omi-rc` from pcie-ep-net v0.3.1 (the helper is
  unchanged).

Full list: [CHANGELOG.md](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/blob/v0.1.1/CHANGELOG.md).

| You want to | File |
| --- | --- |
| Update from v0.1.0-rc.4 or later | LuCI *System → Firmware Update*, or see *Update* |
| Install on other ClusterBox firmware | `openmiop-0.1.1-clusterbox-bmc-openwrt-23.05-mipsel-sysupgrade.bin` + `clusterbox-firmware.json` + `mixtile-update` |
| Teleport agent for the BMC | `teleport-18.10.0-linux-mipsel.gz` (+ `.sha256`) |
| Check what you downloaded | `SHA256SUMS`, `BUILD-INFO.txt` |

## Update

```sh
mixtile-update check && mixtile-update download && mixtile-update verify && mixtile-update install --yes
```

or LuCI **System → Firmware Update** (offered on the `stable` and `rc`
channels). Configuration, `/root/.ssh`, `/home` and `/opt` are kept.

After the reboot:

```sh
cat /etc/mixtile-release            # FIRMWARE_VERSION="v0.1.1"
cat /proc/loadavg                   # ~0 on an idle BMC
dmesg | grep omi0                   # "node N active" seconds after "push mode"
nodectl status --all                # every blade powered, LINK Gen3 x2
```

## Tested

On the lab Cluster Box (four Blade 3 on mixtile-talos v0.3.0, a loaded
Cozystack cluster), with the `omi-rc` of this release (same code, built
by this firmware's CI) loaded by hand on firmware v0.1.0-rc.6:

- module swap: all four blades active 1.7 s after `insmod`; `omi0` ping
  between all blades and the BMC, blade DNS through the BMC;
- `[omi-rc]` in `IW` instead of `DW`; load average 1.08 → 0.27 within
  2 minutes;
- `nodectl reset` of a blade: released, link down 28 ms later, active
  again 10.9 s after the reset, Kubernetes node Ready in 57 s.

The full v0.1.1 image was not flashed before the release; its contents
are verified in CI (`scripts/clusterbox/verify-firmware.sh`).
