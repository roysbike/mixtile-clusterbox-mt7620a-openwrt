# ClusterBox BMC firmware v0.1.0-rc.5

**In one sentence:** the BMC never reads a blade any more, so no blade,
however it goes down, can stop the PCIe fabric.

> [!IMPORTANT]
> **Update every blade first** to pcie-ep-net v0.3
> ([mixtile-talos v0.3.0-rc.1](https://github.com/roysbike/mixtile-talos/releases/tag/v0.3.0-rc.1)).
> The new BMC module leaves blades without push mode alone: an older
> blade would have no `omi0` to the BMC and no peer table. If you cannot,
> `touch /etc/openmiop.use-helper` before updating keeps the old helper.

> [!WARNING]
> Updating reboots the BMC, and the BMC is the PCIe root complex: every
> blade link resets. Blades on pcie-ep-net v0.3 reconnect to each other
> in ~12 s by themselves; with mixtile-talos v0.3.0-rc.1 their NVMe comes
> back too (shared PERST#). On older blade images the NVMe dies and the
> nodes need a reboot. Check `nodectl status --all`, etcd and DRBD after.

## What's new

- **Push mode: `omi-rc` kernel module.** The blades write their state
  into BMC memory; the BMC only writes into blades. A read of a blade in
  flight while its link dropped (crash, power cut) stopped the MT7620A
  root complex until a BMC reboot; that read is gone. `omi0`
  (10.20.0.1, same MAC as before) now comes from the module.
- **Module or helper, chosen at boot.** The `openmiop` init loads
  `omi-rc`; if it does not load, it starts the userspace helper as
  before. `touch /etc/openmiop.use-helper` forces the helper.
- **nodectl 2.0-3** releases a blade through the module before
  `nodectl reset`, `poweroff` and `reboot --hard`.

Full list: [CHANGELOG.md](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/blob/v0.1.0-rc.5/CHANGELOG.md).

## Update

From v0.1.0-rc.4, after all blades run v0.3:

```sh
mixtile-update check && mixtile-update download && mixtile-update verify && mixtile-update install --yes
```

or LuCI **System → Firmware Update**. Configuration, `/root/.ssh`,
`/home` and `/opt` are kept.

After the reboot:

```sh
cat /etc/mixtile-release            # FIRMWARE_VERSION="v0.1.0-rc.5"
dmesg | grep omi0                   # "node N active: ..." for every blade
nodectl status --all                # every blade powered, LINK Gen3 x2
```

Back to the helper without a downgrade:
`touch /etc/openmiop.use-helper && /etc/init.d/openmiop restart`.

## Known issues

- `omi-rc` does not re-enumerate the bridge windows: a blade whose BAR
  got no address is only logged (the helper does it). Not seen with
  the lab blades.
- A blade crash or power cut without a release is harmless by design
  now, but was not tested on purpose.
- A BMC reboot still resets every blade link for the length of its boot.

## Tested

On the lab Cluster Box (4 × Blade 3, Talos with pcie-ep-net 0.3), on
firmware rc.4 with the same `omi-rc` and `nodectl` installed by hand:

- `omi-rc` loaded instead of the running helper: all four blades active
  in 1.6 s, no interruption of blade-to-blade traffic, BMC reaches every
  blade over `omi0`;
- `nodectl reset` of a blade with the module: released, link down 27 ms
  later, blade active again 13 s after the reset, its peers reconnected,
  Kubernetes node Ready in ~2 min;
- not on hardware yet: this firmware image as a whole, the init script
  choosing the module at boot, and an rc.4 → rc.5 update (image contents
  are verified in CI).
