# ClusterBox BMC firmware v0.4.0

**In one sentence:** the BMC firmware moves to OpenWrt 25.12.6 (Linux 6.12)
and gets a web UI built around the box: the cluster and the chassis from
the front on the start page, the network as a live diagram, one place for
every setting, console logs of every blade boot, OpenVPN and WireGuard.

This is the BMC part of **OpenMIOP Stack v0.6.0**, with
[pcie-ep-net v0.6.0](https://github.com/roysbike/pcie-ep-net/releases/tag/v0.6.0)
and [mixtile-talos v0.6.0](https://github.com/roysbike/mixtile-talos/releases/tag/v0.6.0).
The BMC side of OpenMIOP (`omi-rc`) is the same as in pcie-ep-net v0.5.2;
blades on mixtile-talos v0.5.0 and v0.6.0 work with it.

![The start page: the cluster, the box from the front, health and traffic](https://raw.githubusercontent.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/v0.4.0/docs/images/web-ui-cluster.jpg)

> [!WARNING]
> Updating reboots the BMC, and the BMC is the PCIe root complex: every
> blade link resets for ~150 s, and with it all pod traffic between the
> blades. Before the update:
>
> * check that no DRBD replica holds `out-of-sync` bits
>   (`drbdsetup status --verbose --statistics`, all `out-of-sync:0`,
>   [LINBIT/drbd#153](https://github.com/LINBIT/drbd/issues/153));
> * turn off CloudNativePG's primary isolation check
>   (`spec.probes.liveness.isolationCheck.enabled: false`), otherwise a
>   primary that cannot see its replica for those 150 s is shut down and
>   fails over; turn it on again afterwards;
> * back up the configuration (`sysupgrade -b`, SYSTEM → BACKUP).
>
> After the update check `nodectl status --all`, etcd, DRBD and the
> databases.

## Updating from v0.3.0 (OpenWrt 23.05)

The base changes from OpenWrt 23.05 to 25.12 (apk instead of opkg, a
different network layout), so treat it as a reinstall that keeps
`/etc/config`:

1. Back up the configuration and note your port forwards and management
   ports.
2. Install with LuCI *Flash Firmware* or the web UI's firmware upload
   (configuration kept); this is how the lab BMC went to 25.12.
   `mixtile-update install` from v0.3.0 should work the same way but has
   not been tried from 23.05 yet.
3. After the first boot, log in as `mixtile` (the web UI asks to change
   the factory password), check NETWORK → FIREWALL (port forwards to the
   cluster) and SYSTEM → ACCESS (web, SSH and console ports), and restore
   what is missing from the backup.

Packages installed by hand on 23.05 are not kept; install them again
under SYSTEM → SOFTWARE.

## What's new since v0.3.0

**Web UI** (MoCI, patched for the box; LuCI stays at `/cgi-bin/luci`):

* **CLUSTER** — the start page: name, description and the role of every
  slot (EDIT), the box from the front (the BMC, the ASM2824 switch, slots
  1-4 top to bottom with power/PCIe/network LEDs, state, 24 h
  availability, CONSOLE, LOGS and POWER), health, traffic through the BMC.
* **NETWORK** — TOPOLOGY (Internet, router, BMC and each network behind
  it with what is on it), INTERFACES with the WAN fallback address,
  FIREWALL, DHCP & DNS with DNS, DHCP and names for the blades, ROUTES,
  DEVICES, TAILSCALE, WIREGUARD, OPENVPN, DIAGNOSTICS.
* **SYSTEM** — GENERAL (name, time zone, NTP for the blades, reboot),
  ACCESS (ports and zones with automatic roll-back, password), FIRMWARE
  (updates from GitHub with the release notes, manual upload), BACKUP
  (with progress, configuration history and restore), SOFTWARE (apk:
  search, install, remove), STARTUP (enabled at boot, start/stop), LOGS,
  SCHEDULED TASKS, SSH KEYS, STORAGE.
* The login page shows the firmware version with a link to its release.
  After a firmware update the browser loads the new web files by itself.

**Blades and the cluster:**

* Console archive on the BMC's eMMC: every boot of every blade in its own
  file, the LOGS viewer reads, follows, searches and downloads them.
* Node availability log and 24 h bars.
* DHCP on omi0 by default (10.20.0.20-99; gateway, DNS and NTP: the BMC).
  The blades, 10.20.0.205 and the MetalLB pool 210-219 stay static.

**Remote access:** OpenVPN server (one .ovpn per client, certificates
pinned by fingerprint, no CA) and outgoing OpenVPN connections from
uploaded files; WireGuard; Tailscale as before.

**Updates:** the BMC checks for a new release every 12 h and shows a
banner with the release notes; UPDATE downloads, verifies and installs it.

Full list: [CHANGELOG.md](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/blob/v0.4.0/CHANGELOG.md).

## Tested

On the lab Cluster Box with four Blade 3 on mixtile-talos v0.6.0 and a
Cozystack cluster, 2026-10-19/20, with the development builds that led to
this release, each flashed on the BMC:

* All four blades `active ... gateway pull, zero-copy` ~150 s after boot,
  every time; etcd, DRBD and CNPG back without errors.
* Gateway: blade -> LAN 234-245 Mbit/s, LAN -> blade 213-227 Mbit/s
  (10-20 % below 23.05; the BMC CPU is the limit).
* Fabric soak with blade-to-blade and gateway traffic: no errors, no
  stalls.
* Web UI: every page on the BMC; SOFTWARE update/search/install (simulated)
  with apk; OpenVPN server and clients checked with OpenVPN 2.6 against the
  generated files (a removed client is refused).

## Known limitations

* The BMC gateway is limited by the MT7620A CPU (~220-245 Mbit/s).
* A BMC reboot resets every blade link for ~150 s (see the warning above).
* Kernel modules from the OpenWrt feeds only install when they match the
  firmware's kernel.
* Releases are not signed yet (checksums over HTTPS from GitHub).
