## Summary

ClusterBox BMC firmware **v0.1.0-rc.1** for the Mixtile Cluster Box
(MT7620A, OpenWrt 23.05, kernel 5.15.150): node control UI, the
**OpenMIOP** root-complex helper for blade-to-blade Ethernet over the
Cluster Box PCIe fabric, firmware identity in LuCI, and an update checker
that reads this repository's GitHub Releases. Release candidate, part of
OpenMIOP Stack v0.1.0-rc.1. Built by GitHub Actions from the tagged commit
(`BUILD-INFO.txt`); changes in [CHANGELOG.md](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/blob/v0.1.0-rc.1/CHANGELOG.md).

## What's included

| Asset | Purpose |
| --- | --- |
| `mixtile-clusterbox-v120-v0.1.0-rc.1-sysupgrade-sd.bin` | the firmware (kernel + squashfs rootfs + OpenWrt metadata) for sysupgrade onto the BMC microSD |
| `clusterbox-firmware.json` | board, target, version, commit, OpenMIOP protocol, image name and SHA-256 (read by `mixtile-update`) |
| `SHA256SUMS` | checksums of all assets |
| `mixtile-update` | update backend script, for the first install from older firmware |
| `openmiop_*.ipk` | BMC helper package (openmiop-rc, omi-peek, init script) |
| `mixtile-release_*.ipk`, `mixtile-update_*.ipk`, `luci-app-mixtile-update_*.ipk` | firmware identity, update backend, LuCI pages |
| `nodectl_*.ipk`, `luci-app-nodectl_*.ipk` | node control and its LuCI UI |
| `firmware.manifest`, `*.buildinfo`, `BUILD-INFO.txt` | package list, build configuration, feeds, build record |

There is no separate factory image for this target. No BMC kernel module is
built for OpenMIOP (it needs only `kmod-tun`, included). The blade driver is
not part of this firmware.

## Supported hardware

Mixtile Cluster Box control board V120 (`cluster-box-control-V120`,
MediaTek MT7620A, boots from microSD) with the ASM2824 PCIe switch and
Mixtile Blade 3 nodes.

## Installation (first install, from older ClusterBox firmware)

This board's sysupgrade writes kernel and rootfs to the microSD; the ext4
overlay survives. `install-local` first drops overlay files that would
shadow the new firmware (configuration, `/etc/rc.d`, `/root/.ssh`, `/home`,
`/opt` are kept):

```sh
V=v0.1.0-rc.1
B=https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/releases/download/$V
for f in mixtile-clusterbox-v120-$V-sysupgrade-sd.bin clusterbox-firmware.json SHA256SUMS mixtile-update; do
  curl -fLO "$B/$f"
done
sha256sum -c --ignore-missing SHA256SUMS
scp -O mixtile-clusterbox-v120-$V-sysupgrade-sd.bin clusterbox-firmware.json SHA256SUMS mixtile-update root@<bmc>:/tmp/
ssh root@<bmc> "sh /tmp/mixtile-update verify-local /tmp/mixtile-clusterbox-v120-$V-sysupgrade-sd.bin"
ssh root@<bmc> "sh /tmp/mixtile-update prune-preview"
ssh root@<bmc> "sh /tmp/mixtile-update install-local --yes /tmp/mixtile-clusterbox-v120-$V-sysupgrade-sd.bin"
```

Run as root (or with `sudo`). Note extra `opkg` packages first
(`opkg list-installed`); they are not kept.

## Upgrade (from v0.1.0-rc.1 on)

LuCI **System → Firmware Update**, or:

```sh
mixtile-update check && mixtile-update download && mixtile-update verify
mixtile-update install --yes
```

Channel: `rc` by default for this release; `uci set mixtile-update.main.channel=stable && uci commit mixtile-update`
for final releases only. Downgrades need `--allow-downgrade`, a different
OpenMIOP protocol needs `--allow-protocol-change`.

### Recovery

If the BMC does not come back after an update, write the image to the
microSD card on a PC exactly as sysupgrade does (needs the card's existing
Mixtile partition table), then reinsert the card:

```sh
sudo dd if=mixtile-clusterbox-v120-v0.1.0-rc.1-sysupgrade-sd.bin of=/dev/<sdcard> bs=512 seek=16 conv=fsync
```

Blades keep power while the BMC is down; the OpenMIOP fabric pauses until
`openmiop-rc` runs again.

## Verification

```sh
cat /etc/mixtile-release                 # FIRMWARE_VERSION="v0.1.0-rc.1", GIT_COMMIT=<tag commit>
mixtile-update status                    # current version, channel, last_install
pgrep -l openmiop-rc; tail /tmp/openmiop-rc.log    # "node N active" per blade
lspci -d 1d87:4f4d                       # one line per blade
ip addr show omi0                        # 10.20.0.1/24, mtu 9000
ping -c3 10.20.0.<blade>
```

LuCI shows `Mixtile ClusterBox · Firmware v0.1.0-rc.1 · commit <sha> · OpenMIOP v4`
on the login page and in the footer, and a firmware block on Status → Overview.

## Tested configuration

One Cluster Box with four Blade 3 (two Debian 12 / vendor 6.1.99, two Talos
v1.14.2) on OpenWrt 23.05 BMC firmware: the OpenMIOP helper from this source
ran with all four endpoints — five-member ping/jumbo matrix, SHA-256
transfers identical, root-port re-enumeration (forced, blade removed, blade
added). `mixtile-update` status/check/version ordering/prune-preview ran on
that BMC. The contents of this firmware image are checked in CI
(`scripts/clusterbox/verify-firmware.sh`: identity, openmiop helper and
autostart, kernel modules, nodectl, update backend and LuCI pages).

**Not tested on hardware in this release:** booting this firmware build,
`install`/`install-local` (sysupgrade to the microSD), the microSD recovery.

## Performance (OpenMIOP, blade to blade, MTU 9000)

Debian ↔ Debian 8.0-8.3 Gbit/s, Debian → Talos 6.4-6.6, Talos → Debian
7.4-7.5, Talos ↔ Talos 6.5-6.7 Gbit/s (TCP, one stream). Traffic between
blades does not pass through the BMC; blade ↔ BMC gateway ~12 Mbit/s.

## Known limitations

* No A/B rootfs; releases are not signed yet (SHA-256 over HTTPS only;
  signing required before stable v1.0).
* OpenMIOP: blade RX polled, no multiqueue, Talos RX ~20 % slower than
  Debian; root-port re-enumeration pauses the fabric ~1-2 s when a blade
  appears; a blade that disappears without the leave handshake can wedge
  the fabric until the BMC reboots.
* The vendor `miop.ko` from upstream Mixtile firmware stays in the image
  (prebuilt; not used by OpenMIOP).
