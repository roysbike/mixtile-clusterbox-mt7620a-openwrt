# ClusterBox BMC firmware v0.4.5

**In one sentence:** v0.4.4 on the current OpenWrt 25.12 branch: Linux
6.12.116, the MT7620 fix for the MIPS 24K EPC erratum and the newest 25.12
packages.

No v25.12.7 tag exists yet; this release builds the head of the OpenWrt
`openwrt-25.12` branch (`6ad88cfb33`, 81 commits after v25.12.6) with the
packages and luci feeds at their `openwrt-25.12` heads of 2026-11-21.
`omi-rc` and `openmiop-rc` are the same as in v0.4.4 (pcie-ep-net
[v0.7.1](https://github.com/roysbike/pcie-ep-net/releases/tag/v0.7.1)).
The BMC firmware of **OpenMIOP Stack v0.6.x and v0.7.x**; the blades need
no update.

## Why update

* **MT7620 kernel layout.** The MIPS 24K core of the MT7620A can report
  a wrong exception PC for a jump in the first 32 KiB of a memory
  segment; on other MT7620 boards that gave random kernel oopses.
  OpenWrt now keeps kernel and module code out of those 32 KiB, drops the
  old per-call-site workarounds and turns `CONFIG_LIST_HARDENED` on again.
* **Linux 6.12.112 → 6.12.116** (stable fixes).
* **musl:** integer overflows in `regcomp` fixed.
* ucode, libubox, uhttpd, rpcd, fstools, dnsmasq, ca-certificates and
  px5g-mbedtls updates from the branch; luci-base fixes from the luci feed.

## What looks different

* The web UI and `/etc/openwrt_release` show **OpenWrt 25.12-SNAPSHOT**
  instead of 25.12.6: after a release tag OpenWrt removes the `version`
  file from the branch. The apk repositories point to
  `releases/25.12-SNAPSHOT`; install kernel modules only from the
  firmware build, not from there.
* The image is named `openmiop-0.4.5-clusterbox-bmc-openwrt-25.12-mipsel-sysupgrade.bin`.

> [!WARNING]
> Updating reboots the BMC, and the BMC is the PCIe root complex: every
> blade link resets for ~150 s, and with it all pod traffic between the
> blades. Before the update:
>
> * check that no DRBD replica holds `out-of-sync` bits
>   (`drbdsetup status --verbose --statistics`, all `out-of-sync:0`,
>   [LINBIT/drbd#153](https://github.com/LINBIT/drbd/issues/153));
> * turn off CloudNativePG's primary isolation check
>   (`spec.probes.liveness.isolationCheck.enabled: false`) and turn it on
>   again afterwards;
> * back up the configuration (`sysupgrade -b`, SYSTEM → BACKUP).
>
> After the update check `nodectl status --all`, etcd, DRBD, the databases
> and `dmesg` on the BMC.

## Updating from v0.4.3 or v0.4.4

SYSTEM → FIRMWARE → **UPDATE** in the web UI, or over SSH:

```sh
sudo mixtile-update check
sudo mixtile-update download
sudo mixtile-update install --yes --background
tail -f /tmp/mixtile-update/install.log
```

Check the SHA-256 against `SHA256SUMS` first when flashing by hand.
From v0.4.0 to v0.4.2 install over SSH as above (see [v0.4.3](v0.4.3.md)).
From v0.3.0 (OpenWrt 23.05) follow [v0.4.0](v0.4.0.md#updating-from-v030-openwrt-2305).
