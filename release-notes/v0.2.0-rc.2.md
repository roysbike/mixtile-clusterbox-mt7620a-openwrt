# ClusterBox BMC firmware v0.2.0-rc.2

**In one sentence:** the `omi-rc` fix for blades losing the Cluster Box
gateway under heavy load; update the blades too (mixtile-talos
v0.4.0-rc.2), that is where the main fix is.

This is the BMC part of **OpenMIOP Stack v0.4.0-rc.2**, with
[pcie-ep-net v0.4.0-rc.2](https://github.com/roysbike/pcie-ep-net/releases/tag/v0.4.0-rc.2)
and [mixtile-talos v0.4.0-rc.2](https://github.com/roysbike/mixtile-talos/releases/tag/v0.4.0-rc.2).
Either side can be updated first.

> [!WARNING]
> Updating reboots the BMC, and the BMC is the PCIe root complex: every
> blade link resets. Blades on mixtile-talos v0.3.0 or later reconnect to
> each other in ~12 s by themselves and keep their NVMe. Check
> `nodectl status --all`, etcd and DRBD after.

## What's new since v0.2.0-rc.1

- **Gateway fix** (`omi-rc` from pcie-ep-net v0.4.0-rc.2). Under long
  blade -> LAN uploads (BMC CPU at 99 %) a blade on v0.4.0-rc.1 could
  lose the gateway for good: no LAN, internet, DNS or NTP over omi0
  until `omi-rc` was reloaded (`/etc/init.d/openmiop restart`). The
  cause was on the blade (false peer stalls, then a broken reconnect to
  the BMC), fixed in mixtile-talos v0.4.0-rc.2. `omi-rc` now also writes
  the credit to the blade when it resyncs a blade's ring, logs
  `omi0: node N: gateway ring head ..., tail ...: resync` and counts
  `rx_fifo_errors`.

Full list: [CHANGELOG.md](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/blob/v0.2.0-rc.2/CHANGELOG.md).

| --- | --- |
| Update from v0.1.0-rc.4 or later | LuCI *System → Firmware Update* (`rc` channel), or see *Update* |
| Install on other ClusterBox firmware | `openmiop-0.2.0-rc.2-clusterbox-bmc-openwrt-23.05-mipsel-sysupgrade.bin` + `clusterbox-firmware.json` + `mixtile-update` |
| Check what you downloaded | `SHA256SUMS`, `BUILD-INFO.txt` |

## Update

```sh
uci set mixtile-update.main.channel=rc; uci commit mixtile-update   # release candidates
mixtile-update check && mixtile-update download && mixtile-update verify && mixtile-update install --yes
```

After the reboot:

```sh
cat /etc/mixtile-release                      # FIRMWARE_VERSION="v0.2.0-rc.2"
dmesg | grep omi0                             # "node N active: ..., gateway pull" for v0.4 blades
uci get firewall.@defaults[0].flow_offloading # 1
cat /sys/class/net/omi0/statistics/rx_fifo_errors   # 0
nodectl status --all                          # every blade powered, LINK Gen3 x2
```

## Tested

On the lab Cluster Box: firmware v0.2.0-rc.1 with this `omi-rc` code
(credit on resync; built by CI) loaded by hand, .108 on the
pcie-ep-net v0.4.0-rc.2 blade driver (mixtile-talos test image). Stress
round: 3 parallel 300 MB blade -> LAN uploads plus a 300 MB LAN -> blade
download through the BMC, BMC CPU 99 %, then ping the BMC.

| Blade driver | Result |
| --- | --- |
| v0.4.0-rc.1 | gateway lost after 1-4 rounds |
| v0.4.0-rc.2 | 21 rounds, gateway up throughout, 0 stalls; the last 15 during P2P load at 8.7 Gbit/s |

The full v0.2.0-rc.2 image was not flashed before the release; its
contents are verified in CI (`scripts/clusterbox/verify-firmware.sh`).

## Known issues

- The BMC CPU (one MIPS core) is the gateway limit: ~200 Mbit/s to a
  blade, ~230-270 Mbit/s from a blade.
- Otherwise as in [v0.1.1](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/releases/tag/v0.1.1).
