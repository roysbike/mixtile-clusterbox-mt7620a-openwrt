# ClusterBox BMC firmware v0.1.0-rc.6

**In one sentence:** after a BMC boot the blades are back on the BMC
within seconds, not ~5 minutes (fix for rc.5).

> [!WARNING]
> Updating reboots the BMC, and the BMC is the PCIe root complex: every
> blade link resets. Blades on pcie-ep-net v0.3 reconnect to each other
> in ~12 s by themselves; with mixtile-talos v0.3.0-rc.1 their NVMe comes
> back too. Check `nodectl status --all`, etcd and DRBD after.

## What's new

- **`omi-rc` activates the blades right after boot.** With rc.5 the
  module, loaded at ~45 s, left the blades alone until ~300 s of uptime
  (32-bit jiffies starts 300 s before its wrap; two deadlines were 0).
  Blade-to-blade traffic was fine, but the blades' default route, DNS
  and NTP through the BMC timed out for those minutes.

Everything else is as in
[v0.1.0-rc.5](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/releases/tag/v0.1.0-rc.5)
(push mode with `omi-rc`, helper fallback, nodectl 2.0-3). Full list:
[CHANGELOG.md](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/blob/v0.1.0-rc.6/CHANGELOG.md).

## Download

| You want to | File |
| --- | --- |
| Update from v0.1.0-rc.5 or rc.4 | LuCI *System → Firmware Update*, or see *Update* |
| Install on other ClusterBox firmware | `openmiop-0.1.0-rc.6-clusterbox-bmc-openwrt-23.05-mipsel-sysupgrade.bin` + `clusterbox-firmware.json` + `mixtile-update` |
| Teleport agent for the BMC | `teleport-18.10.0-linux-mipsel.gz` (+ `.sha256`) |
| Check what you downloaded | `SHA256SUMS`, `BUILD-INFO.txt` |

## Update

From rc.5 (or rc.4, after all blades run pcie-ep-net v0.3):

```sh
mixtile-update check && mixtile-update download && mixtile-update verify && mixtile-update install --yes
```

After the reboot:

```sh
cat /etc/mixtile-release            # FIRMWARE_VERSION="v0.1.0-rc.6"
dmesg | grep omi0                   # "node N active" seconds after "push mode"
nodectl status --all
```

## Known issues

As in rc.5: `omi-rc` does not re-enumerate bridge windows; a blade
crash or power cut without a release is not tested on purpose; a BMC
reboot resets every blade link for the length of its boot.

## Tested

- rc.5 on the lab Cluster Box (2026-10-12): `omi-rc` loaded by the
  init, helper not running, all four blades active (after the delay
  fixed here), NVMe back on every blade, DRBD and etcd fine.
- The fix itself compiles clean; it is verified by the first boot of
  this image on the lab Cluster Box (not done at tag time).
