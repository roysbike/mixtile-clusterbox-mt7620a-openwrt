# ClusterBox BMC firmware v0.2.0

**In one sentence:** the gateway from the LAN and internet to the blades
is about twice as fast: blades with the v0.4 driver fetch their frames
from BMC memory with their own DMA.

This is the BMC part of **OpenMIOP Stack v0.4.0** (stable), with
[pcie-ep-net v0.4.0](https://github.com/roysbike/pcie-ep-net/releases/tag/v0.4.0)
and [mixtile-talos v0.4.0](https://github.com/roysbike/mixtile-talos/releases/tag/v0.4.0).
Either side can be updated first; blades on mixtile-talos v0.3.0 keep
working with this firmware (old path, same speed as before). Same
content as [v0.2.0-rc.2](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/releases/tag/v0.2.0-rc.2)
apart from the version.

> [!WARNING]
> Updating reboots the BMC, and the BMC is the PCIe root complex: every
> blade link resets. Blades on mixtile-talos v0.3.0 or later reconnect to
> each other in ~12 s by themselves and keep their NVMe. With DRBD 9.3.4
> on the blades, check first that no replica holds `out-of-sync` bits
> (`drbdsetup status --verbose --statistics`, all `out-of-sync:0`): a
> Secondary with stale bits can force-demote the Primary on reconnect
> ([LINBIT/drbd#153](https://github.com/LINBIT/drbd/issues/153)). After
> the update check `nodectl status --all`, etcd, DRBD and the databases.

## What's new since v0.1.1

- **Gateway pull** (`omi-rc` from pcie-ep-net v0.4.0). Until now the BMC
  wrote every frame for a blade into the blade's PCIe BAR with its CPU,
  one 32-bit write per word: ~90 Mbit/s from the LAN to a blade with the
  BMC CPU at 99 %. Now the BMC copies the frame into its own RAM and the
  blade reads it with an eDMA read channel: ~195 Mbit/s.
- **Firewall flow offloading on by default.** Set only if
  `firewall.@defaults[0].flow_offloading` is not set yet.
- **Gateway ring resync** writes the credit to the blade at once, logs a
  warning and counts `rx_fifo_errors` on omi0. Two such warnings when a
  blade reconnects are harmless.

Full list: [CHANGELOG.md](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/blob/v0.2.0/CHANGELOG.md).

## Download

| You want to | File |
| --- | --- |
| Update from v0.1.0-rc.4 or later | LuCI *System → Firmware Update*, or see *Update* |
| Install on other ClusterBox firmware | `openmiop-0.2.0-clusterbox-bmc-openwrt-23.05-mipsel-sysupgrade.bin` + `clusterbox-firmware.json` + `mixtile-update` |
| Check what you downloaded | `SHA256SUMS`, `BUILD-INFO.txt` |

## Update

```sh
mixtile-update check && mixtile-update download && mixtile-update verify && mixtile-update install --yes
```

After the reboot:

```sh
cat /etc/mixtile-release                      # FIRMWARE_VERSION="v0.2.0"
dmesg | grep omi0                             # "node N active: ..., gateway pull" for v0.4 blades
uci get firewall.@defaults[0].flow_offloading # 1
nodectl status --all                          # every blade powered, LINK Gen3 x2
```

## Tested

Lab Cluster Box, 2026-10-13, with v0.2.0-rc.2 (same `omi-rc` code) and
four blades on mixtile-talos v0.4.0-rc.2:

| | Result |
| --- | --- |
| LAN -> blade through the BMC | 193-198 Mbit/s (v0.1.1: 92) |
| Blade -> LAN | 228-238 Mbit/s |
| BMC -> blade, no NAT | 189-204 Mbit/s (v0.1.1: 130) |
| Gateway stress, BMC CPU 99 % | 27 rounds clean (0 stalls, 0 resyncs) |
| Flash (BMC reboot) | all four blades active with gateway pull 47 s after power-on, NVMe live, `rx_fifo_errors` 0 |

The v0.2.0 image itself is verified in CI
(`scripts/clusterbox/verify-firmware.sh`).

## Known issues

- The BMC CPU (one MIPS core) is the gateway limit: ~200 Mbit/s to a
  blade, ~230-270 Mbit/s from a blade.
- See the warning above about DRBD 9.3.4 and BMC reboots.
- Otherwise as in [v0.1.1](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/releases/tag/v0.1.1).
