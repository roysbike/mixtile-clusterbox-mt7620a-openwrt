# ClusterBox BMC firmware v0.3.0

**In one sentence:** the gateway from the LAN and internet to the blades
is ~40 % faster than in v0.2.0: blades with the v0.5 driver read frames
straight from the BMC's buffers, the BMC no longer copies them.

This is the BMC part of **OpenMIOP Stack v0.5.0**, with
[pcie-ep-net v0.5.0](https://github.com/roysbike/pcie-ep-net/releases/tag/v0.5.0)
and [mixtile-talos v0.5.0](https://github.com/roysbike/mixtile-talos/releases/tag/v0.5.0).
Either side can be updated first; blades on mixtile-talos v0.4.0 keep
gateway pull (copy), blades on v0.3.0 the old path.

> [!WARNING]
> Updating reboots the BMC, and the BMC is the PCIe root complex: every
> blade link resets. Blades on mixtile-talos v0.3.0 or later reconnect to
> each other in ~12 s by themselves and keep their NVMe. With DRBD 9.3.4
> on the blades, check first that no replica holds `out-of-sync` bits
> (`drbdsetup status --verbose --statistics`, all `out-of-sync:0`)
> ([LINBIT/drbd#153](https://github.com/LINBIT/drbd/issues/153)). After
> the update check `nodectl status --all`, etcd, DRBD and the databases.

## What's new since v0.2.0

- **Gateway zero-copy** (`omi-rc` from pcie-ep-net v0.5.0). For a unicast
  frame from the BMC's own stack (NAT from the LAN, the BMC itself) to a
  blade with the v0.5 driver, `omi-rc` puts the bus address of the
  frame's buffer into the slot header and the blade's eDMA reads it from
  there; the buffer is freed once the blade has taken the slot.
  Broadcast, multicast and relays between blades are still copied.
  Parameter `zc` (default on).

Full list: [CHANGELOG.md](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/blob/v0.3.0/CHANGELOG.md).

## Download

| You want to | File |
| --- | --- |
| Update from v0.1.0-rc.4 or later | LuCI *System → Firmware Update*, or see *Update* |
| Install on other ClusterBox firmware | `openmiop-0.3.0-clusterbox-bmc-openwrt-23.05-mipsel-sysupgrade.bin` + `clusterbox-firmware.json` + `mixtile-update` |
| Check what you downloaded | `SHA256SUMS`, `BUILD-INFO.txt` |

## Update

```sh
mixtile-update check && mixtile-update download && mixtile-update verify && mixtile-update install --yes
```

After the reboot:

```sh
cat /etc/mixtile-release                      # FIRMWARE_VERSION="v0.3.0"
dmesg | grep omi0                             # "..., gateway pull, zero-copy" for v0.5 blades
uci get firewall.@defaults[0].flow_offloading # 1
nodectl status --all                          # every blade powered, LINK Gen3 x2
```

## Tested

Lab Cluster Box, 2026-10-13/14, with this `omi-rc` code loaded by hand on
firmware v0.2.0; .108 on the v0.5 blade driver, .133 on v0.4.0 at the
same time:

| | v0.2.0 / v0.4 blade | v0.3.0 / v0.5 blade |
| --- | --- | --- |
| LAN -> blade through the BMC | 196-198 Mbit/s | 275-281 Mbit/s |
| BMC -> blade, no NAT | 192-193 Mbit/s | 275 Mbit/s |
| Blade -> LAN | 249-254 Mbit/s | 265-266 Mbit/s |

SHA-256 of a 512 MB random file 3/3 identical; 16 gateway stress rounds
clean; `omi-rc` reload during a download recovered; no memory leak over
2.16 million zero-copy frames. The v0.3.0 image itself is verified in CI
(`scripts/clusterbox/verify-firmware.sh`).

## Known issues

- The BMC CPU (one MIPS core) is still the gateway limit: ~280 Mbit/s to
  a blade, ~250-270 Mbit/s from a blade.
- See the warning above about DRBD 9.3.4 and BMC reboots.
- Otherwise as in [v0.2.0](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/releases/tag/v0.2.0).
