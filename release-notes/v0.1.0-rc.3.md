## Summary

ClusterBox BMC firmware **v0.1.0-rc.3** for the Mixtile Cluster Box (MT7620A,
OpenWrt 23.05, kernel 5.15.150). BMC-only release on top of
[v0.1.0-rc.2](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/releases/tag/v0.1.0-rc.2):
the OpenMIOP helper is unchanged (pcie-ep-net v0.1.0-rc.2, protocol v4).
Changes: [CHANGELOG.md](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/blob/v0.1.0-rc.3/CHANGELOG.md).

- **PCIe link per blade** in LuCI *Cluster* (badge `Gen3 x2`, orange when a
  link trained below what both ends support) and in `nodectl status`
  (LINK column).
- **Firmware updates clean the overlay** again: rc.2's `mixtile-update`
  pruned nothing, so files copied by hand kept shadowing new firmware.
- No more "Temp: no sensor" on the Cluster page.

## Before you update: the fabric goes down

The BMC is the PCIe root complex. While it reboots, every blade loses the
OpenMIOP fabric (omi0) for a few minutes. On the lab cluster, whose node
IPs, etcd and DRBD run over omi0, the rc.2 update left one blade hung (a
hard reset of its slot brought it back) and two DRBD volumes deadlocked
until their nodes were rebooted. Update when a short outage is fine;
afterwards check `nodectl status --all`, etcd and DRBD.

## Update from v0.1.0-rc.2

rc.2's `mixtile-update` has the prune bug, and an update runs the
installed one. Copy rc.3's `mixtile-update` first; it then removes its own
copy together with the other stale files:

```sh
V=v0.1.0-rc.3
B=https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/releases/download/$V
curl -fLO "$B/mixtile-update"
scp -O mixtile-update root@<bmc>:/usr/sbin/mixtile-update
ssh root@<bmc> 'mixtile-update prune-preview'   # what the update removes
```

Then LuCI **System → Firmware Update** → *Check for updates* → *Download &
verify* → *Install update*, or `mixtile-update check && mixtile-update
download && mixtile-update verify && mixtile-update install --yes`.

`install` keeps configuration (`sysupgrade -l`), `/etc/rc.d`, `/root/.ssh`,
`/home`, `/opt`, and removes the overlay files that shadow firmware files.
Files the firmware does not ship stay.

## Install on older ClusterBox firmware

```sh
V=v0.1.0-rc.3
I=openmiop-${V#v}-clusterbox-bmc-openwrt-23.05-mipsel-sysupgrade.bin
B=https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/releases/download/$V
for f in $I clusterbox-firmware.json SHA256SUMS mixtile-update; do curl -fLO "$B/$f"; done
sha256sum -c SHA256SUMS
scp -O $I clusterbox-firmware.json SHA256SUMS mixtile-update root@<bmc>:/tmp/
ssh root@<bmc> "sh /tmp/mixtile-update verify-local /tmp/$I"
ssh root@<bmc> "sh /tmp/mixtile-update install-local --yes /tmp/$I"
```

### Recovery

If the BMC does not come back, write the image to the microSD card on a PC
exactly as sysupgrade does (needs the card's existing Mixtile partition
table): `sudo dd if=<image> of=/dev/<sdcard> bs=512 seek=16 conv=fsync`.
Blades keep power while the BMC is down; the fabric pauses until
`openmiop-rc` runs again.

## Verification

```sh
cat /etc/mixtile-release                 # FIRMWARE_VERSION="v0.1.0-rc.3"
nodectl status --all                     # LINK column: Gen3 x2 per blade
mixtile-update prune-preview             # empty right after the update
ls /overlay/upper/usr/bin                # no openmiop-rc copy left
```

## Tested

- `mixtile-update prune-preview` of the fixed script on the lab BMC
  (running rc.2): lists exactly the hand-copied and vendor files that
  shadow firmware files; keeps `/etc/uci-defaults` whiteouts, the
  Teleport agent and iperf3.
- Link register parsing (Link Status / Link Capabilities) checked against
  the kernel's `current_link_speed` / `current_link_width`.
- Not yet tested on hardware in this firmware build: the LINK column and
  the LuCI badge, and an rc.2 -> rc.3 update. Firmware contents are
  verified in CI on the released image.
