## Summary

ClusterBox BMC firmware **v0.1.0-rc.2** for the Mixtile Cluster Box (MT7620A,
OpenWrt 23.05, kernel 5.15.150): node control UI, the OpenMIOP root-complex
helper for blade-to-blade Ethernet over the Cluster Box PCIe fabric, firmware
identity in LuCI and updates from this repository's GitHub Releases.
Part of OpenMIOP Stack v0.1.0-rc.2. Changes:
[CHANGELOG.md](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/blob/v0.1.0-rc.2/CHANGELOG.md).

**rc.2:** release assets renamed and reduced to what you install; helper
built from pcie-ep-net v0.1.0-rc.2 (same helper source as rc.1).

## What to download

| You want to | Use |
| --- | --- |
| **Update** a BMC that runs v0.1.0-rc.1 | nothing: LuCI *System → Firmware Update*, or `mixtile-update` (below) |
| **Install** on older ClusterBox firmware | `openmiop-0.1.0-rc.2-clusterbox-bmc-openwrt-23.05-mipsel-sysupgrade.bin` + `clusterbox-firmware.json` + `mixtile-update` |
| Verify | `SHA256SUMS`, `BUILD-INFO.txt` |

There is no separate factory image for this target. No BMC kernel module is
needed for OpenMIOP (`kmod-tun` is included).

## Supported hardware

Mixtile Cluster Box control board V120 (`cluster-box-control-V120`,
MediaTek MT7620A, boots from microSD) with the ASM2824 PCIe switch and
Mixtile Blade 3 nodes.

## Update from v0.1.0-rc.1

LuCI **System → Firmware Update** → *Check for updates* → *Download &
verify* → *Install update*, or over SSH:

```sh
mixtile-update check && mixtile-update download && mixtile-update verify
mixtile-update install --yes
```

`install` keeps configuration (`sysupgrade -l`), `/etc/rc.d`, `/root/.ssh`,
`/home`, `/opt`, and removes other overlay files so the new firmware's
files take effect (`mixtile-update prune-preview` lists them).

## Install on older ClusterBox firmware

```sh
V=v0.1.0-rc.2
I=openmiop-${V#v}-clusterbox-bmc-openwrt-23.05-mipsel-sysupgrade.bin
B=https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/releases/download/$V
for f in $I clusterbox-firmware.json SHA256SUMS mixtile-update; do curl -fLO "$B/$f"; done
sha256sum -c SHA256SUMS
scp -O $I clusterbox-firmware.json SHA256SUMS mixtile-update root@<bmc>:/tmp/
ssh root@<bmc> "sh /tmp/mixtile-update verify-local /tmp/$I"
ssh root@<bmc> "sh /tmp/mixtile-update install-local --yes /tmp/$I"
```

Flashing through LuCI *Flash Firmware* works too but leaves hand-copied
overlay files in place (they shadow the new firmware).

### Recovery

If the BMC does not come back, write the image to the microSD card on a PC
exactly as sysupgrade does (needs the card's existing Mixtile partition
table): `sudo dd if=<image> of=/dev/<sdcard> bs=512 seek=16 conv=fsync`.
Blades keep power while the BMC is down; the fabric pauses until
`openmiop-rc` runs again.

## Verification

```sh
cat /etc/mixtile-release                 # FIRMWARE_VERSION="v0.1.0-rc.2"
mixtile-update status                    # last_install "ok v0.1.0-rc.2 ..." after an update
ls /overlay/upper/usr/bin                # no openmiop-rc copy left
pgrep -l openmiop-rc; tail /tmp/openmiop-rc.log    # "node N active" per blade
ip addr show omi0                        # 10.20.0.1/24, mtu 9000
```

## Tested

v0.1.0-rc.1 runs on the lab BMC with four Talos blades on the fabric
(identity, LuCI version display, `mixtile-update status`/`check`/`verify`,
NAT and port forwards to the cluster). This rc.2 image is checked in CI
(identity, helper and autostart, module architecture and vermagic, nodectl,
update backend and LuCI pages). **Not yet hardware-tested:**
`mixtile-update install` (rc.1 → rc.2 is the first OTA update) and the
microSD recovery.

## Known limitations

* No A/B rootfs; releases are not signed yet (SHA-256 over HTTPS).
* No HTTPS in LuCI yet. `uclient-fetch` (TLS 1.2) cannot reach the Talos
  and Kubernetes APIs (TLS 1.3 only).
* OpenMIOP: blade RX polled, no multiqueue; BMC gateway ~12 Mbit/s; NAT
  for blades through the BMC is CPU-bound (MT7620A).
