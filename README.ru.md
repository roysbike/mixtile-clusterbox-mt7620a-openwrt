# Прошивка BMC Mixtile Cluster Box (OpenWrt, MT7620A)

[English](README.md) · [Русский](README.ru.md)

В **Mixtile Cluster Box** стоят четыре вычислительные платы **Mixtile
Blade 3**. Управляющая плата коробки, **BMC** (baseboard management
controller, MediaTek MT7620A), — это собственный маленький компьютер
шасси: он работает всегда, пока на коробку подано питание, что бы ни
происходило с блейдами. Этот репозиторий — открытая прошивка OpenWrt для
этого BMC. Она заменяет прошивку Mixtile и делает BMC единым местом, из
которого управляется вся коробка:

* **Питание и консоли блейдов.** Включить, выключить, перезагрузить
  каждый блейд, открыть его последовательную консоль в браузере и потом
  прочитать любую загрузку любого блейда: консоли записываются на
  накопитель BMC.
* **PCIe-фабрика.** BMC — корневой комплекс PCIe коробки. Его модуль
  `omi-rc` поднимает **OpenMIOP** — Ethernet между блейдами через
  внутренний PCIe-коммутатор (`omi0`, 7-8 Гбит/с на поток между
  блейдами; этот трафик идёт через коммутатор и BMC не касается).
* **Сетевой край кластера.** Блейды выходят в LAN и интернет через BMC
  (NAT, DNS и NTP для блейдов), а сервисы кластера (Kubernetes API,
  ingress) пробрасываются с WAN-адреса BMC.
* **Удалённый доступ** к коробке и кластеру: Tailscale, WireGuard и
  OpenVPN, SSH и веб-интерфейс с защитой, которая откатывает изменение
  доступа, если оно отрезало бы вас от BMC.
* **Наблюдение за коробкой**: какие блейды работают и сколько (история за
  24 часа), фабрика, uplink, проброшенные сервисы, вентилятор и питание.
* **Собственные обновления**: BMC сам ищет новую прошивку в GitHub
  Releases, показывает, что изменилось, и ставит её из веб-интерфейса;
  блейды в это время продолжают работать.

![Веб-интерфейс ClusterBox: страница кластера с коробкой спереди](docs/images/web-ui-cluster.jpg)

*Стартовая страница веб-интерфейса (v0.4.0): сверху кластер, под
ним коробка спереди (BMC, PCIe-коммутатор, слоты 1-4 сверху вниз с
состоянием, доступностью за 24 часа и кнопками CONSOLE, LOGS и POWER),
рядом здоровье и трафик.*

Текущий релиз: **v0.4.0** (OpenWrt 25.12.6, Linux 6.12; OpenMIOP Stack
v0.6.0 и v0.6.1: блейды на mixtile-talos v0.6.1 / Talos v1.14.4 работают
с той же прошивкой) — [release notes](release-notes/v0.4.0.md),
[CHANGELOG.md](CHANGELOG.md),
[страница релиза](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/releases/tag/v0.4.0).
Предыдущий релиз v0.3.0 — на OpenWrt 23.05.

## Оборудование и для кого это

**Mixtile Cluster Box** — компактное шасси на четыре платы **Mixtile
Blade 3**. Внутри:

* BMC: MediaTek MT7620A (MIPS 24KEc, 580 МГц, 256 МБ ОЗУ) с распаянным
  eMMC, WAN-портом 1 Гбит/с, вентиляторами и USB-UART адаптерами консолей
  четырёх блейдов. Он включает, выключает и перезагружает блейды и служит
  корневым комплексом PCIe всего шасси;
* PCIe-коммутатор ASMedia ASM2824 (Gen3): линк Gen3 x2 к каждому слоту и
  линк Gen1 x1 к BMC.

**Mixtile Blade 3** — вычислительная плата на Rockchip RK3588
(4× Cortex-A76 + 4× Cortex-A55) с eMMC и слотом M.2 NVMe. Её контроллер
PCIe 3.0 x4 разделён пополам: линии 0-1 идут к коммутатору Cluster Box,
линии 2-3 — к NVMe. Blade 3 работает и сама по себе, без Cluster Box.

Mixtile поставляет шасси со своей прошивкой BMC и своим сетевым
драйвером для блейдов (MIOP). **OpenMIOP Stack** — независимая открытая
замена для владельцев Cluster Box с платами Blade 3 (или отдельной
Blade 3), которым нужно:

| Что нужно | Репозиторий |
| --- | --- |
| Ethernet между блейдами через PCIe-коммутатор (`omi0`, 7-8 Гбит/с на поток, ~25 Гбит/с при четырёх отправителях) | [pcie-ep-net](https://github.com/roysbike/pcie-ep-net) |
| Talos Linux (Kubernetes) на Blade 3, в Cluster Box или отдельно | [mixtile-talos](https://github.com/roysbike/mixtile-talos) |
| Свежий OpenWrt на BMC: питание и консоли блейдов, PCIe-фабрика, сетевой край кластера, удалённый доступ, обновления прошивки | [mixtile-clusterbox-mt7620a-openwrt](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt) (этот репозиторий) |

## Где стоит BMC

```
        LAN / интернет
              |
   WAN 1 Гбит/с (DHCP)          удалённый доступ: Tailscale, WireGuard, OpenVPN
              |
  +--------------------------------------------------------+
  |  BMC  MT7620A, OpenWrt (эта прошивка)                  |
  |   веб-интерфейс, SSH, nodectl (питание, консоли, логи) |
  |   NAT, DNS, NTP для блейдов, проброс портов            |
  |   omi-rc: omi0 10.20.0.1/24, шлюз блейдов              |
  +--------------------------------------------------------+
        | PCIe Gen1 x1 (управление + шлюз)
   PCIe-коммутатор ASM2824   (трафик между блейдами остаётся здесь)
     |         |         |         |      Gen3 x2 к каждому
  слот 1    слот 2    слот 3    слот 4    Blade 3 (RK3588), omi0 10.20.0.x
```

## Что в прошивке

| Пакет | Что делает |
| --- | --- |
| `kmod-omi-rc`, `openmiop` | сторона OpenMIOP на BMC: `omi-rc.ko` (журнал: `dmesg \| grep omi0`), `/etc/init.d/openmiop`, запасной `openmiop-rc` и `omi-peek` из pcie-ep-net |
| `nodectl`, `luci-app-nodectl` | питание, сброс, консоли блейдов (терминал в браузере), архив консолей, PXE и прошивка блейдов; меню LuCI **Cluster** |
| `clusterbox` | настройки BMC (`/etc/config/clusterbox`): доступ к управлению с защитой от отката, запасной адрес WAN, DNS и NTP для блейдов, постоянный журнал, история конфигурации, журнал доступности нод, описание кластера, состояние прошивки; backend веб-интерфейса в rpcd |
| `moci`, `moci-app-clusterbox` | веб-интерфейс (MoCI, доработанный под коробку) со страницами и разделами ClusterBox, см. [Веб-интерфейс](#веб-интерфейс); LuCI остаётся на `/cgi-bin/luci` |
| `mixtile-release` | `/etc/mixtile-release`: версия, коммит, дата сборки, протокол OpenMIOP |
| `mixtile-update`, `luci-app-mixtile-update` | поиск, загрузка, проверка и установка обновлений из GitHub Releases, фоновая проверка |
| Tailscale, WireGuard, OpenVPN | удалённый доступ (`tailscale`, `kmod-wireguard`/`wireguard-tools`, `openvpn-mbedtls` + `openssl-util` для ключей сервера), страницы в веб-интерфейсе (NETWORK → TAILSCALE, WIREGUARD и OPENVPN) и в LuCI |

### Веб-интерфейс

Три страницы, у каждой настройки одно место (на странице входа — версия
прошивки со ссылкой на её релиз на GitHub):

| Страница | Вкладки |
| --- | --- |
| **CLUSTER** | стартовая: кластер, коробка спереди, здоровье, трафик |
| **NETWORK** | TOPOLOGY · INTERFACES (с запасным адресом WAN) · FIREWALL (с пробросом портов) · DHCP & DNS (с DNS, DHCP и именами для блейдов на omi0) · ROUTES · DEVICES · TAILSCALE · WIREGUARD · OPENVPN · DIAGNOSTICS |
| **SYSTEM** | GENERAL (имя, часовой пояс, NTP для блейдов, перезагрузка) · ACCESS (порты и зоны веб-интерфейса и SSH, пароль) · FIRMWARE (обновления с GitHub и ручная загрузка) · BACKUP (с прогрессом и историей конфигурации) · SOFTWARE (apk: установленные, поиск, установка, удаление) · STARTUP (автозапуск, старт/стоп) · LOGS (с хранением журнала) · SCHEDULED TASKS · SSH KEYS · STORAGE |

DHCP на omi0 включён по умолчанию (10.20.0.20-99; блейды, 10.20.0.205 и
пул MetalLB 210-219 статические) и раздаёт BMC как шлюз, DNS и NTP. Радио
у BMC нет, поэтому страницы Wi-Fi нет.

**CLUSTER**, стартовая страница:

* Сверху — кластер: имя, описание, роль и заметка для каждого слота
  (**EDIT**, хранится в `/etc/config/clusterbox`; BMC не видит Kubernetes,
  поэтому их вписывает оператор), общее состояние и главное: сколько нод
  online, фабрика, WAN, интернет, Tailscale.
* Коробка спереди, как она устроена: BMC сверху (индикаторы питания, WAN
  и PCIe-коммутатора, скорость вентилятора), коммутатор ASM2824 с
  линком к BMC, ниже слоты 1-4 сверху вниз. У каждого слота индикаторы
  питания, PCIe-линка и ответа ноды на проверочный порт, имя, роль, адрес
  и линк (Gen3 x2), состояние и сколько нода в нём, полоса за 24 часа
  (online, загрузка, нет PCIe-линка, выключена, нет данных, пока BMC не
  работал) с долей online и кнопки CONSOLE, LOGS, POWER (выключить,
  перезагрузить, снять питание, включить).
* Рядом: здоровье (ноды, фабрика, интернет, WAN, проброшенные сервисы:
  отвечают или нет, проверка `nodectl probe` раз в 30 с, Tailscale,
  прошивка, шасси), трафик через BMC за 5 минут (трафик между блейдами
  через BMC не идёт), проброшенные сервисы и нагрузка, память, аптайм и
  прошивка BMC.

Страница спрашивает BMC раз в 5 с (`clusterbox topology`), меняет только
изменившиеся значения и не опрашивает BMC, пока вкладка браузера скрыта.
**LOGS** открывает лог консоли ноды: выбор загрузки, чтение с первой
строки, слежение за новым выводом, поиск по всей загрузке, скачивание.

**Обновления прошивки в веб-интерфейсе.** BMC сам ищет новый релиз
(`mixtile-update watch`: через 5 минут после загрузки, потом каждые
12 часов; только проверка, ничего не скачивается): баннер на всех
страницах предлагает его вместе с описанием изменений, а **UPDATE**
скачивает, проверяет (SHA-256, плата, подпись при настроенных ключах) и
ставит его, ждёт BMC и перезагружает страницу. **SYSTEM → FIRMWARE**
показывает работающую прошивку (версия, OpenWrt, ядро, коммит, разделы)
и последнюю проверку. Настройки: `auto_check`, `check_interval` в
`/etc/config/mixtile-update`. Сборкам разработки (`vX.Y.Z-N-g<sha>`)
релизы не предлагаются.

После обновления прошивки браузер сам загружает новые файлы
интерфейса: `/www/moci/version.txt`, хеш файлов, который пишется при
загрузке, читается в обход кеша и подставляется во все адреса (uhttpd
не отдаёт Cache-Control).

### Сеть: топология и VPN

**NETWORK → TOPOLOGY** рисует сеть коробки такой, какая она сейчас, раз в
5 с: интернет и роутер выше по сети, BMC (адрес и линк WAN, трафик,
проброс портов, зоны firewall) и каждую сеть за ним с тем, что в ней:
`omi0` (PCIe-фабрика) с четырьмя блейдами и адресами проброшенных
сервисов, Tailscale, сервер OpenVPN с клиентами, исходящие подключения
OpenVPN и интерфейсы WireGuard.

**NETWORK → OPENVPN**:

* *Сервер* — удалённый доступ к BMC (веб-интерфейс, SSH) и к сети блейдов
  10.20.0.0/24 с ноутбука или телефона. **SET UP THE SERVER** спрашивает
  адрес, к которому подключаются клиенты, порт, протокол и подсеть
  клиентов; **ADD CLIENT** создаёт клиента и скачивает его `.ovpn` (его
  можно скачать ещё раз позже), **DELETE** закрывает этому клиенту
  доступ. Удостоверяющего центра нет: у сервера и у каждого клиента свой
  самоподписанный EC-сертификат, и каждая сторона проверяет SHA-256
  отпечаток другой (`peer-fingerprint`). Ключи хранятся на BMC в
  `/etc/openvpn/cb/` и переживают обновление прошивки. WAN-адрес BMC
  обычно частный: пробросьте порт на него на роутере.
* *Подключения к другим VPN-серверам* — загрузите `.ovpn` с другой
  стороны (офис, облачная сеть), и BMC подключится по нему. Директивы,
  запускающие программы (`up`, `script-security`, `plugin`, …),
  отклоняются. Подключения, настроенные в LuCI (**VPN → OpenVPN**), тоже
  показываются.

У WireGuard своя вкладка (**NETWORK → WIREGUARD**, страница MoCI),
Tailscale — в **NETWORK → TAILSCALE**.

### Логи консолей и доступность

Последовательная консоль каждого блейда (USB-UART CH343 на BMC,
1,5 Мбод) записывается `nodectl consoled` на eMMC BMC, по файлу на каждую
загрузку блейда: `/overlay/log/nodectl/nodeN/YYYYmmdd-HHMMSS.log` (длинная
загрузка продолжается в частях `.pNNN.log` по `console_archive_part_mb`),
каждая строка с временем BMC. Новый файл начинается при включении или
сбросе через `nodectl`, по баннеру U-Boot или ядра и когда отметки
времени ядра идут назад (блейд перезагрузился сам). Самые старые
загрузки удаляются сверх `console_archive_mb` (512) или
`console_archive_boots` (100) на блейд; настройки в `/etc/config/nodectl`.
Архив лежит вне upper-каталога overlay, обновление прошивки его не трогает.

`availwatch` (пакет `clusterbox`) каждые 20 с проверяет, есть ли у блейда
питание, PCIe-линк и отвечает ли он на проверочный порт, и записывает
каждое изменение в `/overlay/log/clusterbox/availability`.

## Установка и обновление

Первая установка со старой прошивки Cluster Box — `mixtile-update
install-local`, см. [First install](README.md#first-install-from-older-clusterbox-firmware).
С v0.1.0-rc.1 и новее:

```sh
mixtile-update check && mixtile-update download && mixtile-update verify && mixtile-update install --yes
```

или LuCI **System → Firmware Update**. Настройки, `/root/.ssh`, `/home` и
`/opt` сохраняются.

> [!WARNING]
> Обновление перезагружает BMC, а BMC — корневой комплекс PCIe: линки всех
> блейдов сбрасываются примерно на 150 с, вместе с ними — весь трафик подов
> между блейдами. Перед обновлением: DRBD без `out-of-sync`
> ([LINBIT/drbd#153](https://github.com/LINBIT/drbd/issues/153)), у
> CloudNativePG выключить проверку изоляции primary
> (`spec.probes.liveness.isolationCheck.enabled: false`, после обновления
> включить обратно), сделать резервную копию настроек. После обновления
> проверьте `nodectl status --all`, etcd, DRBD и базы данных.
> С v0.3.0 (OpenWrt 23.05) переход — смена базы: проверьте проброс
> портов и порты управления, см. [release notes v0.4.0](release-notes/v0.4.0.md).

## Если BMC не загрузился после обновления

Съёмной карты у BMC нет: ядро, система и overlay лежат на распаянном
`mmcblk0`, на SPI-флеш только U-Boot и заводские данные. Пока BMC не
работает, блейды тоже без LAN (их Ethernet идёт через свитч BMC).

Восстановление заводской прошивки кнопкой reset: выключить питание,
зажать reset на BMC, включить и держать, пока не замигает светодиод,
затем отпустить. BMC загрузится с заводской прошивкой Mixtile и
заводскими настройками; нужный релиз ClusterBox ставится заново через
LuCI *Flash Firmware*. Настройки при этом теряются, поэтому перед каждым
обновлением сохраните их:

```sh
sysupgrade -b /tmp/bmc-config.tar.gz   # затем скопировать с BMC
uci export > /tmp/bmc-uci.txt          # читаемая копия
```

### Serial-консоль BMC (UART)

На плате контроллера есть трёхконтактный разъём UART для MT7620A: у края
платы, рядом с кнопкой и батарейкой RTC. Штыревой разъём 2,54 мм не
распаян, его нужно впаять. Контакты слева направо, как на фото Mixtile
([UART of Controller Board, PDF](https://downloads.mixtile.com/blade3/file/UART%20of%20Controller%20Board.pdf)):

| Контакт | Куда на USB-UART адаптере (например, FT232) |
| --- | --- |
| TX | RX |
| RX | TX |
| GND | GND |

Адаптер на 3,3 В. Mixtile указывает скорость **57600** (8N1). В этой
прошивке ядро пишет в `console=ttyS0,115200`: если после загрузчика
пошёл мусор, переключите терминал на 115200. На лабораторном стенде ещё
не использовалось; так можно увидеть, почему прошивка не загружается.

```sh
picocom -b 57600 /dev/ttyUSB0      # Ctrl-A Ctrl-B — сменить скорость
```

## Проверка

```sh
cat /etc/mixtile-release
lsmod | grep omi_rc; dmesg | grep omi0            # "push mode", "node N active" для каждого блейда
nodectl status --all                              # все блейды включены, LINK Gen3 x2
ping -c3 10.20.0.<блейд>
```

Сборка, подробности восстановления и известные ограничения — в
[README.md](README.md).
